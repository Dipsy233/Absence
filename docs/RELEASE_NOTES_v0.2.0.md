# Release v0.2.0 — Personalized Avatars & Agent Eggs Filters / 个性化形象与 Eggs 过滤

**WhaleBun (鲸团团) · Settings dialog · upload-your-own animations · egg filter profiles**

This release is about making Absence *yours*: the agent's avatar can now be your
own animation, and the process panel shows what *you* consider worth watching —
both configured from a new settings dialog, no code and no URLs.

---

## ✨ Highlights / 亮点

### 🐋 The avatar is now WhaleBun (鲸团团)
The built-in HTML character is renamed across assets, code and docs — and it is
no longer the only option.

### 🎨 Upload your own avatar animations — no URLs, no code
The `⚙ settings` button opens a three-pane dialog. The left pane manages
**avatar skins**:

- Create a skin — its name is a folder under `avatar-skins/` on the server.
- Pick a status (`default` / `listening` / `thinking` / `speaking` / `reading` /
  `searching` / `editing` / `running` / `waiting` / `error`) and upload a file:
  **mp4 / gif / png / webp / svg**.
- The file becomes that status's animation. Re-uploading replaces it; `✕` clears it.
- Statuses without a file fall back to the skin's `default`; anything still
  missing renders the built-in WhaleBun character — a half-finished skin works.
- `Apply` activates the skin; switch back to WhaleBun to restore the built-in.
- Updates go live within seconds — no reload, no restart.

**Videos just work**: uploads are re-encoded server-side with ffmpeg
(video-only stream, metadata/data tracks stripped, H.264 main, yuv420p,
`+faststart`), so Chrome never shows the broken-image icon. The media endpoint
supports HTTP Range requests (`206`), which `<video>` requires. If a file still
can't be decoded, the panel shows a hint instead of a broken image.

Files land in `apps/server/src/process/avatar-skins/<skin>/<status>.<ext>` and
are served at `/avatar/<status>`.

### 🥚 Agent Eggs filter profiles
The right pane manages **named profiles** of helper command names. The process
classifier treats a listed name as a tool — folded into the helper count
instead of cluttering the panel.

- Same name saves **overwrite** the profile file; a **new name creates** one.
- The saved profile is **active immediately**.
- A `force` option extends filtering to the command's *declared subject* —
  e.g. filter `node` even in `node ticker.mjs &`. A process that outlived its
  command stays visible either way: that is the one signal no name can fake.
- Profiles live in `apps/server/src/process/egg-filters/<name>.json`.

### ⚙️ Settings dialog, three panes
| Pane | What it configures |
|---|---|
| **Avatar skin** (left) | skins, per-status uploads, activation |
| **Settings** (middle) | color theme (`amber`/`blue`/`green`) + stacking order of both side rails' panels |
| **Eggs filter** (right) | filter profiles + `force` |

The dialog is rendered through a portal (it can't be clipped or dragged away by
the frameless title bar) and closes on Esc or a click on the backdrop.

## 📡 New HTTP API

```
GET    /api/egg-filter                        profiles + active + names
PUT    /api/egg-filter/:name                  { names, force? } → save & activate
POST   /api/egg-filter/:name/activate         activate a saved profile
DELETE /api/egg-filter/:name                  delete a profile

GET    /api/avatar-skins                      skins + active + files
POST   /api/avatar-skins/:name                create an empty skin folder
PUT    /api/avatar-skins/:name/files?status=&filename=   raw bytes → one status
DELETE /api/avatar-skins/:name/files/:status  clear one status
DELETE /api/avatar-skins/:name                delete a skin
POST   /api/avatar-skins/:name/activate       activate (empty = built-in)
GET    /avatar/:status                        active skin's media (Range ok)
```

## 📦 Upgrade notes

- **Restart the server** and hard-refresh the browser (`Ctrl+Shift+R`) — both
  the raw-body parser and the media endpoint are server-side changes.
- The runtime data directories (`avatar-skins/`, `egg-filters/`) are gitignored;
  the server seeds sensible defaults on first boot.
- Requires `ffmpeg` on `PATH` for the video re-encoding; without it the
  original file is kept as-is.
