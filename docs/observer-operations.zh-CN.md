# 旁观监控：启动、选择目标与中途挂载

这是 `re` 分支当前的使用方式。Windows 和无桌面的 Linux 都只运行同一个 Web 服务；桌面壳只是可选的浏览器入口。agent 仍由用户在终端启动和操作。Absence 不发送提示词、不代答审批、不停止 agent。

## 从源码运行

在 agent 所在主机上执行 `npm ci`、`npm run build`，再启动服务：

```sh
npx tsx apps/server/src/cli.ts serve
```

另一台有桌面的机器可以通过 SSH 转发访问（服务仍仅绑定回环）：

```sh
ssh -N -L 8848:127.0.0.1:8848 user@agent-host
```

打开 `http://127.0.0.1:8848` → 观测台 → 选择目标 → 进入面板。不要把含有转录和文件路径的服务直接暴露到公网。若显式绑定非回环地址，服务要求访问令牌（`ABSENCE_TOKEN`）；令牌不能代替加密传输。

无浏览器也可以在 agent 主机的另一个终端选择目标：

```sh
npx tsx apps/server/src/cli.ts ls
npx tsx apps/server/src/cli.ts observe --pid 12345
npx tsx apps/server/src/cli.ts observe --session /absolute/path/to/session.jsonl
npx tsx apps/server/src/cli.ts unwatch <sessionId>
```

`observe` 打印面板 URL。PID 只能选择 Absence 已识别的目标，不表示支持任意进程。进程归因以 PID 与启动时间区分实例；转录与进程没有足够的关联证据时，不应仅凭工作目录强行绑定。

## 中途挂载有哪些事实

| 通道 | 挂载前 | 挂载后 |
|---|---|---|
| pi 转录 | 按记录顺序回填可读的完整 JSONL 记录；找到真实用户消息就保留真实 run 边界。记录从回合中间起步时，首个 run 标记为开头缺失，不补造提示词 | 同一解析器继续尾随；没有换行结尾的记录等写完再读 |
| 仅 OS | 只能看到挂载时仍存在、可归因的进程；无法恢复已退出的短进程、过去的采样或对话 | 采样进程活动和资源；不把活动区间伪装成对话回合 |
| ACP 代理（可选） | 不是对现有终端进程的中途注入，不能回放未经过代理的流量 | 仅记录通过代理的事实 |

默认发现只列目标，不创建监控会话；点击监控或执行 `observe` 后才创建租约。`ABSENCE_AUTO_ATTACH=1` 可恢复按近期转录自动挂载的旧行为。关闭面板不撤销租约；`unwatch` 撤销租约，不杀进程、不删除历史，也不强制立即关闭已有面板。服务可恢复已保存的租约，归档按外部会话身份复用。

**目前的边界：**超过 200 MiB 的转录不全量回填。恢复已有归档时，解析器目前会跳过重读的历史以避免重复，这也可能跳过停服期间写入的记录；下一步应在归档事务中持久化已消费的记录位置并校验文件身份，再从断点补录。OS 采样空窗则无法补录，应单独标记，不能以为转录回填也能恢复它。
