# Absence v0.4.0 —— 持久化、指标与验证

[English](v0.4.0.md) | [简体中文](v0.4.0.zh-CN.md)

> 本文描述 v0.4.0 发布时的状态。下文所述的 Classic 布局——右栏、Stage 页面以及
> FILE / DIFF / TERMINAL / LIVE 内容视图——已在 v0.5.0 被
> Rounds / Monitor / Chart 三个 face 取代。

v0.4.0 建立在 v0.3.0 的运行时集成之上。它把会话历史迁到 SQLite，新增资源指标，
并把 `npm run verify` 作为完整的验收门禁。

## 用户可见变化

### SQLite 会话历史

- 会话、事件、run 与文件版本存储在 `~/.absence/absence.db`，使用 WAL 模式。
- 旧的 JSONL 归档一次性导入，并保留为备份。
- History 增量索引；历史 Activity 按 run 加载，无需把整个会话装进浏览器。
- 文件版本有独立索引，与 History 视图解耦。

### 资源指标

- 对 agent 的主 egg 采样 CPU 与 RSS，并通过 WebSocket 以 metrics frame 发送。
- 实时 ring 保留最新 300 帧。
- 更长的时间范围与历史会话从 SQLite 的 metric chunk 读取，默认保留 30 天，并
  提供会话级平均值。
- 右栏 METRICS 面板与完整的 Stage 仪表盘支持选择 egg，并查看 `1m`、`5m`、`30m`、
  `1h` 与 `all` 范围。
- 已退出的 egg 从观察到的退出时刻起不再计入生命周期平均值。
- 已退出 egg 的最后一次样本仍可查看，其摘要标记为 exited。

### Stage 与状态模型

- METRICS 成为 Stage 的默认页。FILE、DIFF、TERMINAL、LIVE 是内容视图；replay 仍
  由事件与快照重建。
- 增量折叠保证实时事件窗口滑动时 Agent Eggs、History 与 Activity 仍然正确，且
  不必为每个事件重建整个窗口。
- Agent 文件视图保留未读行段的缺口，并可在同一路径的多个已记录版本之间切换。

### 验证

- `npm run verify` 运行 workspace 类型检查、生产 Web 构建与全部离线验收检查。
- 离线覆盖包含指标存储、增量折叠与项目外变化归因。
- mock History 检查覆盖 75 条断言，包括分页、replay、Metrics 默认页、文件缺口与
  版本切换。
- 桌面 server bundle 与独立 server 生命周期有各自检查。

## 破坏性变更

- 要求 Node `>=22.19`。SQLite 由 Node 内置的 `node:sqlite` 提供，版本要求写在
  `package.json` 与 `.nvmrc`。
- `ABSENCE_STATE_DIR` 必须指向支持 SQLite WAL 的文件系统；两个同时运行的实例
  不能使用同一个数据库。
- 需要重启服务器并硬刷新浏览器（`Ctrl+Shift+R`）。
- 已有 JSONL 归档在首次访问时自动导入，并保留为备份。
- v0.4.0 的界面布局已在 v0.5.0 被替换。升级不需要迁移操作，但 METRICS 默认页
  与 FILE / DIFF / TERMINAL / LIVE 内容视图已不存在。

## 已知限制

- 指标默认保留 30 天；超过保留期的 chunk 会被删除，除非修改保留设置。
- 资源指标按固定节奏采样。短于该节奏的进程可能不出现在曲线上。
- 历史指标从已持久化的 chunk 读取；超出实时 ring 的范围需要对应 chunk 已写入。
- Agent Folder 的文件缺口按 agent 上报的内容保留。读取未携带行号时，视图把范围
  标记为 unknown。
- 上文描述的 Classic 布局属于 v0.4.0 的界面。v0.5.0 引入的 face 改变了阅读方式，
  不改变已存储的数据。
