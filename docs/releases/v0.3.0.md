# Absence v0.3.0 — Codex, DSH and shell takeover

[English](v0.3.0.md) | [简体中文](v0.3.0.zh-CN.md)

> These notes describe v0.3.0 as released. The Codex app-server client,
> exec-server shell takeover, AbsenceShell, ExecServer, CodexShell,
> ShellEnvironment and the per-product Codex and DSH adapters described below
> were removed in v0.5.0. The original v0.3.0 text described them in the present
> tense; that became incorrect after v0.5.0. Current agent integration is
> described in [v0.5.0](v0.5.0.md).

v0.3.0 extended Absence from Pi to Codex and DSH. At the time, Absence drove
Codex through `codex app-server` and took over its shell through a loopback
exec-server, while DSH ran through its ACP server. Those three mechanisms were
removed in v0.5.0.

## User-visible changes

### Codex runtime

- Codex became selectable in the project picker, and `ABSENCE_AGENT=codex`
  selected it without the picker.
- Absence drove `codex app-server`, the JSON-RPC channel Codex defined for
  observers. Unlike `codex exec --json`, it carried item ids, call ids and
  timestamps, so a command's lifecycle paired with the processes it laid.
- The Stage, Activity, Replay, Absence Report, Agent Eggs, Agent Folder and the
  chat commands (`/model`, `/thinking`, `/permission`) worked unchanged. The web
  application still consumed only `AbsenceEvent`.

### DSH runtime

- Absence spawned `dsh --profile acp`, DSH's ACP server, and drove it over
  JSON-RPC/NDJSON on stdio. `DshClient` was the transport and `DshAdapter` mapped
  `session/update` notifications to `AbsenceEvent`.
- Message, thinking, tool, file, command and search events mapped;
  `usage_update` became context usage.
- DSH read results were unwrapped: the `<path>…<content>NN: line…` wrapper was
  stripped so a `file_read` had the same shape as Pi's plain text.
- Every shell tool call opened a `ProcessWatcher` window (`begin` on `tool_call`,
  `end` on `tool_call_update`), so Agent Eggs saw the processes the agent laid.
- `session/request_permission` became an `approval` event; the chosen ACP option
  id was returned to the agent.
- DSH was located from an explicit path (`ABSENCE_DSH_BIN` or a saved path) or
  from `dsh` on `PATH`. Configuration used `ABSENCE_DSH_BIN`,
  `ABSENCE_DSH_PROFILE`, `ABSENCE_DSH_HOME`, `ABSENCE_DSH_PROVIDER` and
  `ABSENCE_DSH_MODEL`.

### Shell takeover for Codex

Pi's shell was Absence's own (`AbsenceShell`), which let Absence see every
process a Pi command laid. Codex ran in its own process, so Absence started a
loopback exec-server, registered it with `environment/add`, and pinned the
thread to it. Codex then handed every command to Absence as a `process/start`,
and Absence spawned it itself.

This addressed two observation gaps:

- A detached launch (`Start-Process`, a background daemon) previously went
  through the shell (`explorer.exe`), outside the Job Object, and disappeared
  from Agent Eggs. It became Absence's own child and was attributed like any
  other process.
- An exit was observed first-hand as the child closed, without depending on a
  kernel message that a burst-killed process tree could drop.

`ABSENCE_CODEX_EXEC_SERVER=0` rolled back to Codex's own executor; the observer
still ran, with the older limits.

### Real PTY

Absence used `node-pty` (ConPTY on Windows) for `tty: true`. Ctrl+C was handled:
a `process/signal interrupt` was answered with a process-tree kill.

### Agent Eggs exit fix on Windows

The Job Object completion port could drop an `EXIT_PROCESS` message when a whole
tree was killed at once. The observer also waited on each process handle
(`RegisterWaitForSingleObject`), a kernel signal that could not be lost.

### Session attribution

An environment marker was used only to exclude another session's processes,
never as a requirement for attribution. This made Linux capture work.

### Configurable Absence Report attention

- `command_failed` fired only after a configurable number of failed commands in
  one run (default 5) and raised a configurable level.
- `command_failure_streak` fired after a configurable number of consecutive
  failures with no success between them (default 3, level medium).
- `activity_stalled` fired when no event arrived for a configurable number of
  seconds while the run was live (default 3600 s, level medium).
- All thresholds and levels were set in the Settings dialog's **REPORT WARN**
  pane (levels: none / low / medium / high). An unrecovered failure stayed high
  regardless of thresholds.

### Custom sound sets

- Audio could be uploaded per event (`attention`, `complete`, `approval`) in the
  Settings dialog to replace the synthesized WebAudio chimes. Events without a
  file kept the built-in chime.
- The server stored sets under `sound-sets/<set>/<event>.<ext>` with an
  `active.json`, and served the active set at `/sound/<event>` with HTTP Range;
  `?set=` auditioned a specific set.
- The web interface provided preview, clear and activate controls.

### Runtime discovery and the picker

- `agents/PiBin.ts` resolved the `@earendil-works/pi-coding-agent` package from a
  configured path, `ABSENCE_PI_BIN`, the global npm install, or the copy
  resolved from Absence's tree, and reported the source and version. The SDK was
  loaded through `loadPiSdk()`; a bare specifier was not used.
- `GET` / `POST /api/runtimes` and `~/.absence/runtimes.json` persisted binary
  paths; `ABSENCE_CODEX_BIN` seeded Codex. The picker gained a runtime paths
  panel with an availability dot per runtime.
- When a requested runtime could not start, the session failed with an error
  shown in the picker. Spawn failures (`ENOENT`) were handled events, not server
  crashes.

### Chat dock and Settings

- The conversation stayed above the Stage at all times, so report, file, diff and
  terminal sheets did not cover it.
- A new `APPEARANCE` setting, *collapse on content*, folded the chat history
  when a content page opened. It was off by default.
- The Settings dialog had four panes: `APPEARANCE` (theme, panel order,
  collapse on content), `REPORT WARN`, `PERSONALIZATION` (avatar skins and sound
  sets in one column) and `EGGS FILTER` (profile sidebar with a `+` action,
  label editing, and a *display in activity* toggle that hid the LAID/DIED rows
  from Activity while keeping the eggs in Agent Eggs).

### Launchers and test infrastructure

- `start-absence.bat` / `.sh` and the desktop launcher rebuilt only when the
  output was older than a source file. `--force` rebuilt anyway.
- The eleven check scripts shared one harness (`scripts/checks/harness.ts`) with
  `check()`, `finish()` and `waitFor()`.
- `npm run check:offline` ran every offline check in one process-spawning pass;
  the script list was registered only in `scripts/checks/run-offline.ts`.
- CI ran `check:offline` on Node 22, matching `engines.node`.
- `check-report.ts` grew to 72 checks and `check-history.ts` to 63 assertions.
- `make-demo.mjs` defaulted to `./absence-demo`.

## Breaking changes

- Node `>=22.19` was required, matching `engines.node`; CI moved from Node 20 to
  Node 22.
- `node-pty` became a new native dependency for `tty: true`. It shipped prebuilt
  binaries.
- Linux packages were added: `desktop:dist` emitted an AppImage and a `tar.gz`
  alongside the Windows NSIS installer.
- The server had to be restarted and the browser hard-refreshed
  (`Ctrl+Shift+R`).
- New environment variables: `ABSENCE_AGENT=codex|dsh`, `ABSENCE_CODEX_BIN`,
  `ABSENCE_CODEX_SANDBOX`, `ABSENCE_CODEX_APPROVAL`,
  `ABSENCE_CODEX_APPROVAL_DECISION`, `ABSENCE_DSH_BIN`, `ABSENCE_DSH_PROFILE`,
  `ABSENCE_DSH_HOME`, `ABSENCE_DSH_PROVIDER`, `ABSENCE_DSH_MODEL`.
- New HTTP API in v0.3.0: `GET` / `POST /api/runtimes`; `GET` / `POST
  /api/sounds[...]` and `GET /sound/:event`. The egg-filter and avatar-skin
  endpoints from v0.2.0 were unchanged.

Capabilities removed in v0.5.0:

- The per-product adapters, including `PiAdapter`, `CodexAdapter` and
  `DshAdapter`, were deleted, along with the `DshClient` transport. Agents are
  driven through the ACP access layer described in [v0.5.0](v0.5.0.md).
- The `codex app-server` client and the exec-server shell takeover were deleted.
  `ABSENCE_CODEX_EXEC_SERVER` no longer exists.
- `AbsenceShell`, `ExecServer`, `CodexShell` and `ShellEnvironment` were deleted.
  `ABSENCE_PI_TOOLS` was removed with them.
- Capability configuration management, which read and wrote the agent's
  `mcp.json`, skills and `config.toml`, was deleted.
- Pi private session file merging was deleted. History now comes from the
  Absence archive; observe mode still reads Pi and Codex transcripts for tool
  and MCP events but does not merge them as history.
- Absence-implemented slash commands (`/model`, `/skill`, `/mcp`, `/thinking`)
  were deleted. Slash lines are forwarded verbatim; `/auth` is the only action
  Absence implements itself.
- The `codex`, `execserver`, `shellenv` and `codexshell` check scripts were
  removed with the corresponding implementations.

## Known limitations

- The shell-takeover guarantees applied only to Codex through its exec-server.
  After v0.5.0 removed that path, those guarantees no longer apply.
- DSH support at v0.3.0 depended on a DSH build that provided
  `--profile acp`. After v0.5.0, DSH is launched through an ACP profile and the
  dedicated adapter no longer exists.
- Report attention levels could be configured, but an unrecovered failure
  remained `high` regardless of the configured threshold.
- The panel-order and *collapse on content* settings belonged to the Classic
  layout. They were removed in v0.5.0.
- The Windows exit fix reduced lost exit messages; attribution remained
  dependent on the process being visible to the Job Object or the sampled
  process table.
