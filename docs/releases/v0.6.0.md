# Absence v0.6.0 — Observation only

[English](v0.6.0.md) | [简体中文](v0.6.0.zh-CN.md)

> These notes describe v0.6.0. This release removed the ACP access layer that
> v0.5.0 introduced: Absence no longer starts, drives or answers for any agent,
> and every write-back path is refused. Capabilities that were removed are
> listed under Breaking changes.

Absence is an observer now. The agent runs in its own terminal, in its own
session, under its own account; Absence reads what that agent already writes and
what the operating system already knows. Three read-only channels feed one event
pipeline, and a session that Absence did not originate is still a session it can
show.

## User-visible changes

### Three observation channels

- **Channel A — transcript tails.** `observe/` follows the session files the
  agent software writes on its own (pi format; `ABSENCE_OBSERVE_PI_ROOT`
  overrides the root). Discovery lists targets without opening a session;
  selecting one (`POST /api/observe/watch`, or `absence observe`) attaches it
  with a full backfill. `ABSENCE_AUTO_ATTACH=1` restores recency-based
  auto-attach.
- **Channel B — the ACP proxy.** A proxy session spawns its agent into a
  persisted observed session (channel `acp-proxy`), injects
  `ABSENCE_SESSION_ID` for exact kernel attribution, and projects the client's
  prompt as the run boundary. `absence proxy -- <command>` is the entry point.
- **Channel C — OS observation.** A machine-wide scanner (`ExternalScanner`)
  hands every observed transcript its bound process subtree. Default-pi runs
  bind by unambiguous 1:1 pairing scoped by process cwd, and always to the
  transcript the process wrote last — a session resumed mid-run (`-c`, the
  resume picker) is followed on its new file, never the one it started with.
- A pi process names its conversation three ways and all three are resolved:
  `--session <absolute path>`, `--session <id>` (matched through the transcript
  header) and a bare `pi` (project cwd plus latest write). Windows
  extended-length paths (`\\?\C:\…`) are stripped before comparing. A pi the
  command line cannot prove is still listed as an OS-only target, with its
  working directory as the row title and the pid as its own field.
- Kernel-level observation: selecting a running pi attaches a dedicated
  observer to that pid. On Windows `agentwatch --target-pid <pid>` adopts the
  process into its own Job Object; on Linux the machine-wide eBPF stream is
  filtered by ancestry. The subtree is reported as events rather than sampled,
  and the table sweep remains the fallback when no kernel observer can attach.

### The board is the front door

- The web app is the Observatory: it lists transcripts, proxies and history,
  and never launches an agent.
- The board has two columns — running targets on one side, history on the
  other. Clicking a session monitors it and the click becomes *stop*; there is
  no per-row stop button. A running row shows its first prompt, like a history
  row does.
- The launcher, the "+ Chat" affordances, the chat input, the slash palette,
  the approval buttons and `/model` switching are gone; the approval card is
  read-only.
- A history row (or a `/s/<id>` deep link) reopens its archive read-only
  instead of returning 404. An OS-only watch that gains a transcript backfills
  the conversation, and its archive's process facts are not mistaken for
  transcript history and warmed away.

### Reading a transcript truthfully

- One `edit` tool call is one `file_edit` fact. pi sends a list of replacements
  for a single file; emitting one event per replacement put five identically
  stamped rows in the feed whose timeline marks overlapped, so only the last was
  reachable. A recent call is reconstructed into the whole file before/after
  from disk (one event, `fullContent: true`); an older one stays one event with
  the reported snippets and their combined diff.
- Timeline lanes carry their own duration: an assistant record's `durationMs`
  closes the thought or reply at the generation's end, and a `toolResult`'s
  `durationMs` places its command where it actually ran, so the Shell lane no
  longer paints over the model's thinking.
- Runs follow the channel that now feeds the session. Folding a transcript into
  a process watch switches the run index from activity bursts to user turns,
  rebuilds the rows already written (they had been labelled `usage` / `tool_end`
  by their first event), and stops the burst timer from closing a turn the agent
  is still writing. Retiring a burst session closes its open run instead of
  leaving a `running` row nobody will ever finish.
- Mid-session attachment is honest: backfill streams in chunks (a record may
  span chunks), the first run is marked `attach`/`truncatedBefore` with no
  invented prompt, and appends during a backfill are read once at the end.

### Archive and resume

- SQLite schema v5 adds `sessions.channel` and `sessions.external_id` (the
  observation identity) and `runs.boundary_source`. Re-attaching after a restart
  reuses the archive row instead of duplicating it, and an observed session
  archives automatically after `ABSENCE_ARCHIVE_SILENCE_MS` of silence with no
  viewer.
- SQLite schema v7 adds `transcript_checkpoints`: the consumed byte offset and a
  SHA-256 of the prefix are stored in the same transaction as the events. A
  restart resumes only after the prefix verifies, so offline appends are
  recovered without duplicating history. A rewritten or truncated transcript
  stops the merge and the board shows `transcriptResumeBlocked`, and an orphan
  checkpoint is dropped instead of aborting a flush.

### Command line

`absence` is a headless entry point: `serve`, `ls`, `observe`, `open`, `unwatch`
and `proxy`. `serve` starts the server (the default), `ls` lists the targets this
host can monitor, `observe` selects one and prints its panel URL, `open` prints a
session's panel URL, `unwatch` drops a monitor lease while keeping the archive.
`ABSENCE_URL` and `ABSENCE_TOKEN` address a server that is already running.

### Platform

- Windows Docker capture is force-disabled: no WSL daemon probing, and no
  environment variable re-enables it. Container attribution on other platforms
  works from transcript command windows.

## Breaking changes

- Absence drives no agent. The ACP drive stack (`AcpAdapter`, `AcpConnection`,
  `AcpSession`, the permission bridge, auth, config options, `AgentCatalog`,
  the built-in profiles and `createAdapter`'s real path) was removed.
  `createAdapter` resolves only the mock fixture; every other session is
  observed and answers 403 on the write-back routes.
- The chat is gone: the input, the slash palette, approval buttons, `/auth` and
  `/model`, and every command that wrote to a session. `/model` was introduced
  in v0.5.5 and is removed here; the model is chosen in the agent's own
  terminal.
- The agent picker, agent discovery, `~/.absence/agents.json` custom entries,
  the ACP registry cache, runtime discovery and `ABSENCE_*_BIN` overrides no
  longer exist as launch paths. `ABSENCE_ALLOW_NPX` and `allowNpx` are gone with
  them.
- `GET /api/agents*`, `GET /api/runtimes*` and the session write-back routes
  were removed. Starting a session is `POST /api/observe/watch` instead.
- There is no terminal mirror and no PTY: Absence never starts an agent, so it
  has no terminal to mirror.
- Sessions are identified by observation identity, not by a launch. An archive
  row whose channel and external id match an existing observed session is
  reused; the old per-product session keying does not exist any more.
- Docker capture is disabled on Windows and no environment variable re-enables
  it.
- The desktop shell and the browser both open the board; a deep link is
  `/s/<sessionId>`.

## Known limitations

- Transcript reading covers the pi format only. An agent that writes no
  transcript can still be watched as an OS-only target, but Absence sees its
  process tree, files and commands, not its conversation.
- Binding a transcript to a process needs evidence. When the command line names
  neither a session file nor a session id, and no single process is the only
  candidate, the target is listed OS-only and its conversation stays out of the
  archive. An ambiguous pairing is never guessed.
- Kernel observation exists only with the committed native helpers. Without one,
  the table sweep samples the tree: short-lived processes can be missed, and
  orphans are not attributed.
- Docker observation requires a reachable daemon, and containers started outside
  a command window are not attributed. On Windows container capture is off.
- Absence never starts, resumes or stops the observed agent. Closing a panel
  drops a monitor lease; the agent keeps running, and so does everything it
  spawned.
- Replay and the Absence Report still work from the archived event slice and
  still do not rebuild metrics, Agent Eggs or terminal bytes. There are no
  terminal bytes any more, because Absence has no terminal.
- Re-watching a target refreshes its monitor lease instead of creating a second
  one, and re-attaching after a restart reuses the archive row rather than
  duplicating the session.
- Linux kernel observation needs `CAP_BPF` and `CAP_PERFMON` (or root). Without
  them the loader refuses and the session falls back to polling, with the reason
  shown on the target's status.
- `absence ls`, `observe`, `open` and `unwatch` are thin clients over a running
  server; they read `ABSENCE_URL` and `ABSENCE_TOKEN` rather than a local
  archive, so there is nothing to ask unless a server is up.
