# Absence v0.5.5 — Cost, report access and the observing contract

[English](v0.5.5.md) | [简体中文](v0.5.5.zh-CN.md)

> These notes describe v0.5.5. This release kept the v0.5.0 ACP access layer and
> the three faces; v0.6.0 replaced that access layer with observation and
> refused every write-back path.

v0.5.5 spent its budget where an always-on window pays for it: what Absence
costs while nothing happens, and the report it owes a caller that has no
browser.

## User-visible changes

### Idle cost and memory

- Liveness probing stopped walking the process table. `ProcessWatcher.checkAlive`
  asks the OS about each egg's own pid (`kill(pid, 0)`) instead of running a full
  PowerShell/`ps` snapshot every 5 s.
- The process-table snapshot — session baseline, fallback sweep and metric
  fallback — is read natively instead of through PowerShell/CIM. `agentwatch`
  gained a `table` stdin command: a Toolhelp32 walk, one handle per process, one
  JSON row per line. It measured 17 ms for 386 rows against 1.19 s of CPU and a
  ~100 MB transient working set for the CIM pass. CIM stays as the degraded
  path when no helper is live.
- Monaco loads as a lazy chunk. The main bundle fell from ~3.9 MB to ~750 KB, and
  editors mount behind `useMonacoReady`, so no CDN fallback is attempted.
- A history refresh reads only the archive tail after the last `seq` instead of
  re-reading the whole session.
- `FileWatcher` reuses the file tree's ignore list, so `.next`, `.nuxt`, `.hg`
  and `.svn` are no longer walked.
- Metric summaries are capped at 512 rows. A session quiet for 5 minutes is
  evicted only after its chunk has been flushed, and its rows are read back from
  SQLite when the session is reopened.
- Electron log writes are asynchronous.

### Absence Report without a browser

- The report engine — `buildRunFacts`, `renderLive` and `renderRun` — moved from
  `apps/web` to `@absence/core` as a pure, deterministic module. The web app
  re-exports it under the previous paths, so existing imports are unchanged.
- `GET /api/sessions/:id/report` returns `{ run, report, facts }` for the latest
  run; `?run=<n>` selects run #n (1-based). A server, a CI job or the desktop
  shell gets the identical report with no browser in the loop.
- An idle run is no longer reduced twice a second. The reduction is cached on the
  run identity, the event slice's tail (length plus last id) and the attention
  options, so an appended chunk still rebuilds within the 500 ms beat and a
  settings change still invalidates it.

### Chat

- `/model` is a port action again: when the agent advertises a `model` config
  option, `/model` lists its values and `/model <model>` applies one with
  `session/set_config_option`, the same call shape as `/auth`. An agent that
  advertises no selector has no `/model` entry, and a typed `/model …` line is
  forwarded verbatim as a prompt.

### Fixes

- A write tool that creates a 0-byte file is captured. An empty `content` is a
  real write, missing content falls back to the file on disk (`source: os`), and
  the call still leaves a `file_change` when even disk is unavailable. ACP's raw
  `kind` and `title` are carried through unchanged, and the agent-status label
  follows `kind` before any tool-name match.
- A file a shell command created reads as CREATE, not EMPTIED, and the Files tab
  badge counts every file the agent demonstrably touched instead of reads only.
- The picker card reads as two lines — path · date, then meta · session id — and
  the id sits in the corner: the flex rules are scoped to win the cascade
  against the older `span { display: block }` rule.
- The picker matches paths slash-agnostically, so `E:\…` and `E:/…` find the
  same stored history, and cards show the project's absolute path.
- Panels follow the newest run once one arrives. A replayed run no longer pins
  every panel to itself after returning to live.
- The desktop shell binds a stable port — the previous launch's choice first,
  then 8848, 8849 and 8850 — and remembers it in `userData/server-port`. A stable
  origin is what lets the UI's `localStorage`-scoped settings persist at all;
  before this fix every desktop launch got a fresh origin and a fresh, empty
  store.
- Agent launch resolves its executable with a pure path scan (the current
  directory and `PATH` in order, the bare name then each `PATHEXT` extension)
  instead of spawning `where`. The `PATHEXT`-priority selection is unchanged.
- The agentwatch check asserts the current folding: an executor-shaped shell
  (`cmd /c`, `bash -c`) is plumbing, not an egg.

## Breaking changes

- Absence never terminates a process. Closing a session Absence drove used to
  `taskkill /T` its command subtrees (`SIGTERM` on POSIX) and reap leftover eggs;
  `terminateCommands`, `terminateTrackedPosix`, `killTree` and the
  `SessionStore.dispose()` call are gone. Commands an agent started keep running
  after the session closes, and the `process_left_running` attention reason is
  the signal that they are still there.
- A fresh install starts in the `glass` style with the dark scheme instead of
  `nixie`.
- The embedded desktop server no longer binds an arbitrary free port. It uses the
  remembered port, then 8848, 8849 or 8850. Settings stored under the old random
  origin do not carry over to the new one.

## Known limitations

- The native table snapshot is Windows-only; Linux still reads `/proc`.
- Report facts come from the archived event prefix up to the run's end. A run
  whose events were trimmed by the 10,000-event archive cap reports what
  survived.
- Evicting a metric summary costs one SQLite read when that session is reopened;
  the live ring is not restored with it.
- `/model` depends on the agent advertising a model config option. An agent that
  switches models only through its own terminal picker shows nothing.
- Commands and orphaned eggs left behind by a closed session are reported and
  watched to their exit, but Absence provides no way to stop them.
