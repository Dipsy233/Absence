# Absence v0.5.0 —— ACP 接入层与界面重构

[English](v0.5.0.md) | [简体中文](v0.5.0.zh-CN.md)

> 本文描述 v0.5.0。本版本移除了 v0.3.0 引入的各产品专用接入路径；被移除的能力
> 列在“破坏性变更”一节。

## 用户可见变化

### 统一的 ACP 接入层

- Absence 通过单一 ACP 客户端路径驱动 agent：`AgentCatalog` → `AcpAdapter` →
  `AcpConnection` → agent 进程。各产品专用适配器与私有协议已删除。
- 内置 profile：`pi`、`codex`、`codex-acp-alt`、`dsh`、`claude-code`、
  `qwen-code`、`gemini`。
- 新 agent 以数据方式接入：`~/.absence/agents.json` 中的自定义条目（`id`、
  `label`、`command`、`args`、`env`、`cwd`），或 ACP registry 条目。不需要新增
  代码分支。
- 发现顺序：显式 launch line 或 `ABSENCE_*_BIN`；`PATH` 上的 ACP 二进制；本地
  `node_modules` 下的适配器包；agent CLI 自带的 ACP 模式（例如
  `gemini --acp`）；npx 仅在 `ABSENCE_ALLOW_NPX=1` 或 `allowNpx: true` 时启用。
  只有 CLI、没有 ACP 入口时标记为 `needs-adapter`。
- 就绪状态：`ready`、`needs-adapter`、`needs-auth`、`unavailable`。选择器不显示
  `unavailable`。
- 协商 ACP 协议版本 1；版本不同则关闭连接。线格式是 NDJSON 上的 JSON-RPC 2.0。
  `session/new` 发送 `{ cwd, mcpServers: [] }`；MCP 配置由 agent 自己读取。
- 会话恢复优先使用 agent 声明的 `session/resume`，其次 `session/load`，都没有时
  新建会话。`session/close` 仅在 agent 声明时发送。
- Absence 默认不声明 `fs` 与 `terminal` 客户端能力，因此 agent 发来的
  `fs/read_text_file`、`fs/write_text_file` 与 `terminal/*` 请求会收到 JSON-RPC
  错误。

### Agent 选择器

- 选择器是探测方格；每行显示就绪状态、发现来源、声明模型、认证状态、能力说明与
  安装提示。不可用的 agent 不占格子。
- 最后一格是 `+` 自定义 ACP 条目，包含 `id`、`label`、`command`、`args`、
  `env`、`cwd`，保存在 `~/.absence/agents.json`。
- 提示流把所选 agent 的认证、模型来源与 launch 覆盖作为同级 note 显示。
- History 列表可恢复之前的会话。

### 聊天、审批与认证

- 命令面板列出 agent 广告的命令，外加 `/auth`。
- 其他 `/…` 行按原文作为 prompt 转发。Absence 不实现本地的 model、skill、MCP 或
  thinking 命令。
- `/auth <methodId>` 调用 agent 的 `authenticate`。Absence 不读取 token、不代填
  凭据、不代理 OAuth。
- `session/request_permission` 成为 `approval` 事件。选项来自 agent，用户选中的
  option id 原样回传。选择拒绝类选项时，该工具调用标记为 `permissionDenied`。
  取消回合时，先把挂起的审批答为 cancelled，再取消回合。

### 事件保真

- 每条事件带 `source` 与 `fidelity`（`exact`、`reported`、`inferred`、`unknown`）。
- 协议缺失的字段标记为 unknown，不补值。未报告行号的文件读取带
  `rangeKnown: false`；无法重建的编辑带 `fullContent: false`；没有退出码的命令带
  `exitCodeKnown: false`。

### 界面

- 三个可切换 face：Rounds、Monitor、Chart。Drip 是叠加在当前 face 上的开关，不是
  第四个 face。默认 face 是 Monitor。
- Monitor：Activity、Files、Attention 三个标签；Stage 渲染活动卡片，页面标签只有
  METRICS 与 CHAT，没有 FILE / DIFF / TERMINAL 切换条。右栏包含 Agent Head、
  Usage、Agent Eggs 与 Agent Folder。
- Rounds：桌面式布局，包含 story 条、角色，以及 Files、Agent Folder、Agent
  Eggs、Run、文件版本与按 egg 指标等浮动窗口。
- Chart：以整页形式显示 Absence Report。
- Drip：折叠为球或胶囊。桌面壳为它提供独立的置顶窗口；浏览器使用 Document
  Picture-in-Picture。
- Settings 有四栏：Appearance（语言、主题 `nixie` / `ink` / `glass`、色系
  dark / light、聊天 Markdown）、Report WARN、Personalization（头像皮肤与音效集）
  以及 Agent Eggs 过滤档案。

### Replay 与 Absence Report

- Replay 由 run 事件与快照重建文件内容、agent 状态与当前 Stage 动作，速度
  0.25× 至 10×。它不重建指标、Agent Eggs 或终端字节。
- Absence Report 在 Web 端由某个 run 的事件切片计算；服务端不计算，也不调用
  LLM。报告包含时间线、读取、搜索、变化、命令、MCP 调用、进程、恢复、循环与
  注意力。
- 注意力原因：`command_failed`、`command_failure_streak`、`activity_stalled`、
  `process_left_running`、`outside_change`、`file_version_loop`、
  `command_retry_loop`。阈值与等级可在 Report WARN 中配置。

### Agent Eggs、Agent Folder 与指标

- Agent Eggs 的内核来源是 Windows Job Object 或 Linux eBPF。内核助手不可用时退化
  为进程表采样，并标记 `sampled`。进程分类为 `primary` 或 `tool`；面板只列
  primary egg，tool 折叠为计数。
- Docker 容器蛋使用 `docker events` 获取生命周期、`docker stats` 获取资源。容器
  使用合成 pid，只有命令窗口内启动的容器才归因。
- Agent Folder 列出 agent 读、写、编辑过的文件。读取版本累积 agent 实际看到的
  行段；写入与编辑版本是完整文件。diff 只使用完整版本。
- 每 5 秒为 agent 树、每个 egg、Docker 容器与主机采样：CPU、RSS、VSZ、线程、
  句柄（仅 Windows）与 IO。实时 ring 保留 300 帧；SQLite 保存 chunk，默认保留
  30 天。
- Monitor 的 run 选择器显示每个 run 的事件数、时长、开始时间与计数。

### 归档与代理

- SQLite 归档支持分页事件回放、归档删除，以及通过
  `ABSENCE_SESSION_RETENTION_DAYS` 与 `ABSENCE_MAX_ARCHIVED_SESSIONS` 配置的会话
  保留策略。
- `absence proxy -- <cmd>` 与 `POST /api/acp-proxy/sessions` 原样转发 ACP 行，并
  通过旁路 tap 投影事件。代理不替客户端回答请求。
- CLI 子命令：`absence`、`absence serve`、`absence proxy`。

### 打包

- Windows 发布在 NSIS 安装器之外新增免安装 ZIP（`Absence-0.5.0.zip`）。Linux
  发布提供 AppImage 与 `tar.gz`。
- 发布产物命名为 `Absence.Setup-<版本>.exe`、`Absence-<版本>.zip`、
  `Absence-<版本>.AppImage`、`Absence-<版本>.tar.gz`。

### 修复

- agent 的启动 chunk 按 metadata 处理，不再被当作一个 speaking 回合；新建会话不再
  卡在 speaking。
- 停止未被确认时，界面本地解锁。
- 静默溢出与看门狗强制了结如实报错。
- 流式工具输出累积，不再只保留最后一个 chunk。
- ACP 工具调用接受 argv 数组与 null `rawInput`，不臆造值。
- 文件读取范围不再由内容行数推断；缺失范围标记为 unknown。
- JSON-RPC `error.data` 的详情保留在错误事件中。
- ACP 代理在两端关闭后释放句柄。
- Windows shim 按 `PATHEXT` 解析，批处理文件以安全方式启动。
- 关闭 Absence 驱动的会话时，回收其命令子树。
- 被孤立的 Linux server 能检测到父进程已退出。

## 破坏性变更

- 各产品专用适配器 `PiAdapter`、`CodexAdapter`、`DshAdapter` 已删除。agent 通过
  ACP profile 运行。
- `codex app-server` 客户端与 exec-server shell 接管已删除。
  `ABSENCE_CODEX_EXEC_SERVER` 及相关 `ABSENCE_CODEX_*` 调参变量不再存在。
- `AbsenceShell`、`ExecServer`、`CodexShell`、`ShellEnvironment` 已删除。
  `ABSENCE_PI_TOOLS` 随之移除。
- capabilities 配置管理已删除。Absence 不再读写 agent 的 `mcp.json`、skills 或
  `config.toml`。
- Pi 私有会话文件合并已删除。历史只来自 Absence 归档。已有 JSONL 归档在首次
  访问时一次性导入；`piSessionFile` 与 `piSessionId` 列名保留以兼容旧数据。
- Absence 自己实现的斜杠命令（`/model`、`/skill`、`/mcp`、`/thinking`）已删除。
  斜杠行按原文转发；`/auth` 是唯一的本地动作。
- `GET /api/sessions/:id/commands/:name/options` 已删除。命令选项由 agent 的
  `configOptions` 与 `available_commands_update` 承载。
- 会话快照与状态中的 `capabilities` 字段已删除，`AgentProfile.discoverCapabilities`
  已删除。
- Classic 布局已删除：左栏、中央 Stage、右栏、FILE / DIFF / TERMINAL / LIVE
  内容标签、侧栏面板顺序、collapse-on-content，以及 Absence Report 浮层。它们由
  face 与 Chart 页面取代。
- Settings 随布局改变。旧的 `amber` / `blue` / `green` 配色主题由 `nixie` /
  `ink` / `glass` 主题与 dark / light 色系取代。头像皮肤移入 Personalization
  栏。
- 升级后需要重启服务器并硬刷新浏览器（`Ctrl+Shift+R`）。
- npx 兜底默认关闭，除非设置 `ABSENCE_ALLOW_NPX=1` 或 `allowNpx: true`。
  Absence 不会隐式下载 agent。

## 已知限制

- 头像皮肤、音效集与 Agent Eggs 过滤档案存储在安装目录。打包为只读目录后，上传
  会失败。
- 只有在 Windows 助手持有进程句柄，或 Linux eBPF 能看到进程时，Agent Eggs 才是
  exact。采样模式可能漏掉短命进程；并发命令的进程可能被归到相邻命令；孤儿进程
  不归因。界面不提供杀进程操作。关闭 Absence 驱动的会话时会回收其命令子树。
- ACP 语义层依赖 agent 上报的内容。缺失工具 `kind` 时按字段形状规则处理；缺失
  `locations` 时文件范围标记为 unknown。
- transcript 读取只支持 Pi 与 Codex 两种布局。
- Absence 以 PTY 启动 agent 时，服务端会生成终端镜像；当前 Web 界面不连接该终端
  WebSocket。
- Replay 不重建指标、Agent Eggs 面板或终端字节。
- Absence Report 不调用 LLM，也不解析命令语义。缺失退出码报告为 unknown。未恢复
  的失败不受配置阈值影响，始终为 high。
- 会话运行期间，归档最多保留 10,000 条事件。流式消息与 thinking 事件不落盘。
- Docker 观察以 daemon 可用为前提。命令窗口外启动的容器不归因；buildx 基础设施
  会被过滤。
- 指标最小采样节奏为 5 秒；更短的进程可能从未出现在曲线上。Linux 不报告句柄数，
  IO 读数依赖 `/proc/<pid>/io` 可读。
- 选择器没有编辑 profile launch line 的界面，也没有 allowNpx 开关；两者通过环境
  变量、`~/.absence/agents.json` 或 HTTP API 设置。
