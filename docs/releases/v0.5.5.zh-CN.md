# Absence v0.5.5 —— 开销、报告接口与旁观契约

[English](v0.5.5.md) | [简体中文](v0.5.5.zh-CN.md)

> 本文描述 v0.5.5。本版本保留 v0.5.0 的 ACP 接入层与三个 face；v0.6.0 用旁观
> 取代了该接入层，并拒绝所有写回路径。

v0.5.5 把预算花在一个常驻窗口真正要付账的地方：什么都不发生时 Absence 的开销，
以及它欠一个没有浏览器的调用方的报告。

## 用户可见变化

### 空闲开销与内存

- 存活探测不再遍历进程表。`ProcessWatcher.checkAlive` 直接向操作系统询问每个 egg
  自己的 pid（`kill(pid, 0)`），不再每 5 秒执行一次完整的 PowerShell/`ps` 快照。
- 进程表快照——会话基线、回退扫描与指标回退——改由原生助手读取，不再走
  PowerShell/CIM。`agentwatch` 新增 `table` 标准输入命令：一次 Toolhelp32 遍历，
  每个进程一个句柄，每行一条 JSON。实测 386 行用时 17 ms，而 CIM 那一趟是
  1.19 秒 CPU 与约 100 MB 的瞬时工作集。没有可用助手时仍回退到 CIM 降级路径。
- Monaco 作为懒加载分块加载。主包从约 3.9 MB 降到约 750 KB，编辑器在
  `useMonacoReady` 之后挂载，因此不会尝试 CDN 兜底。
- 历史刷新只读取最后一个 `seq` 之后的归档尾部，不再每次重读整个会话。
- `FileWatcher` 复用文件树的忽略表，`.next`、`.nuxt`、`.hg`、`.svn` 不再被遍历。
- 指标摘要上限为 512 行。安静 5 分钟的会话只在其分块落盘之后才被淘汰，重新打开
  会话时其行从 SQLite 读回。
- Electron 日志写入改为异步。

### 不依赖浏览器的 Absence Report

- 报告引擎——`buildRunFacts`、`renderLive` 与 `renderRun`——从 `apps/web` 移到
  `@absence/core`，成为纯函数、确定性的模块。Web 端在原路径重新导出，已有导入
  无需改动。
- `GET /api/sessions/:id/report` 返回最新 run 的 `{ run, report, facts }`；
  `?run=<n>` 选择第 n 个 run（从 1 开始）。服务端、CI 任务或桌面壳都能拿到同一份
  报告，不需要浏览器参与。
- 空闲的 run 不再每秒重算两次。结果按 run 身份、事件切片的尾部（长度与最后一条
  的 id）以及关注度选项缓存，因此新追加的分块仍会在 500 ms 节拍内重建，设置变化
  也仍会失效缓存。

### 聊天

- `/model` 重新是一个端口动作：当 agent 广告了 `model` 配置项时，`/model` 列出
  可选值，`/model <model>` 用 `session/set_config_option` 应用其中一个，调用形状
  与 `/auth` 相同。没有广告选择器的 agent 没有 `/model` 条目，手输的 `/model …`
  行仍按原文作为 prompt 转发。

### 修复

- 创建 0 字节文件的写入工具调用会被捕捉。空 `content` 是真实写入；缺失 content
  时回退到磁盘上的文件（`source: os`）；即使磁盘也不可读，调用仍会留下一条
  `file_change`。ACP 原始 `kind` 与 `title` 原样透传，agent 状态标签先看 `kind`
  再看工具名。
- 由 shell 命令创建的文件读作 CREATE，而不是 EMPTIED；Files 标签的角标统计 agent
  确实触碰过的每一个文件，而不只是读取。
- 选择器卡片读作两行——路径 · 日期，然后是元信息 · 会话 id——且 id 落在角落里：
  新规则限定在选择器作用域内，以赢得与旧 `span { display: block }` 规则的层叠。
- 选择器按斜杠无关的方式匹配路径，`E:\…` 与 `E:/…` 都能找到同一份历史，卡片显示
  项目的绝对路径。
- 面板在有新 run 到达后跟随最新的 run。被回放的 run 不再在回到实时后把每个面板都
  钉在自己身上。
- 桌面壳绑定稳定端口——优先上次启动的选择，其次 8848、8849、8850——并记录在
  `userData/server-port`。稳定的 origin 才是 UI 中 `localStorage` 设置得以持久化
  的前提；修复之前每次启动桌面版都得到新的 origin 与空存储。
- agent 启动改用纯路径扫描解析可执行文件（先当前目录再 `PATH`，先裸名再依次尝试
  各 `PATHEXT` 扩展），不再 spawn `where`。`PATHEXT` 优先级选择不变。
- agentwatch 检查对齐了当前的折叠规则：执行器形状的 shell（`cmd /c`、`bash -c`）
  属于管线，不是 egg。

## 破坏性变更

- Absence 不再终止任何进程。关闭 Absence 驱动的会话曾经会 `taskkill /T` 其命令
  子树（POSIX 上 `SIGTERM`）并回收遗留 egg；`terminateCommands`、
  `terminateTrackedPosix`、`killTree` 与 `SessionStore.dispose()` 调用均已移除。
  agent 启动的命令在会话关闭后继续运行，`process_left_running` 关注度原因就是它们
  仍在的信号。
- 全新安装以 `glass` 样式与 dark 色系启动，不再是 `nixie`。
- 内嵌桌面服务端不再绑定随机空闲端口。它使用记录的端口，其次 8848、8849、8850。
  存储在旧随机 origin 下的设置不会迁移到新 origin。

## 已知限制

- 原生进程表快照仅限 Windows；Linux 仍读取 `/proc`。
- 报告事实来自截至该 run 结束的归档事件前缀。事件被 10,000 条归档上限裁掉的 run
  只报告存活下来的部分。
- 淘汰指标摘要在重新打开该会话时会产生一次 SQLite 读取；实时环形缓冲不会随之
  恢复。
- `/model` 依赖 agent 广告了模型配置项。只在自身终端选择器里切换模型的 agent 不会
  出现任何条目。
- 已关闭会话遗留的命令与孤儿 egg 会被上报并观察到其退出，但 Absence 不提供任何
  停止它们的方式。
