# Absence v0.5.0 — ACP access layer and UI rebuild

[English](v0.5.0.md) | [简体中文](v0.5.0.zh-CN.md)

> These notes describe v0.5.0. This release removed the per-product access paths
> introduced in v0.3.0; the removed capabilities are listed under Breaking
> changes.

## User-visible changes

### One ACP access layer

- Absence drives agents through a single ACP client path: `AgentCatalog` →
  `AcpAdapter` → `AcpConnection` → the agent process. Per-product adapters and
  private protocols are gone.
- Built-in profiles: `pi`, `codex`, `codex-acp-alt`, `dsh`, `claude-code`,
  `qwen-code`, `gemini`.
- New agents can be added as data: a custom entry in `~/.absence/agents.json`
  (`id`, `label`, `command`, `args`, `env`, `cwd`) or an ACP registry entry. No
  code branch is required.
- Discovery order: an explicit launch line or `ABSENCE_*_BIN`; an ACP binary on
  `PATH`; a local adapter package under `node_modules`; the agent CLI's ACP mode
  (for example `gemini --acp`); npx only when `ABSENCE_ALLOW_NPX=1` or
  `allowNpx: true`. A CLI without an ACP entry reports `needs-adapter`.
- Readiness states: `ready`, `needs-adapter`, `needs-auth`, `unavailable`. The
  picker hides `unavailable`.
- ACP protocol version 1 is negotiated; a different version closes the
  connection. JSON-RPC 2.0 over NDJSON is the wire format. `session/new` sends
  `{ cwd, mcpServers: [] }`; the agent reads its own MCP configuration.
- A session resumes through `session/resume` when the agent declares it, then
  `session/load`, and otherwise starts a new session. `session/close` is sent
  only when declared.
- Absence declares no `fs` or `terminal` client capabilities by default, so
  `fs/read_text_file`, `fs/write_text_file` and `terminal/*` requests from the
  agent receive JSON-RPC errors.

### Agent picker

- The picker is a probe grid; each row shows readiness, discovery source,
  declared model, auth state, capability note and an install hint. An
  unavailable agent takes no cell.
- The last cell is `+`, a custom ACP entry with `id`, `label`, `command`,
  `args`, `env` and `cwd` stored in `~/.absence/agents.json`.
- A hint stream shows the selected agent's auth, model source and launch
  override as peer notes.
- The History list restores previous sessions.

### Chat, approvals and auth

- The command palette lists commands the agent advertises, plus `/auth`.
- Any other `/…` line is forwarded verbatim as a prompt. Absence implements no
  local model, skill, MCP or thinking command.
- `/auth <methodId>` calls the agent's `authenticate`. Absence does not read
  tokens, fill credentials or proxy OAuth.
- `session/request_permission` becomes an `approval` event. Options come from
  the agent, and the chosen option id is returned as-is. A rejecting option
  marks the tool call `permissionDenied`. Cancelling a turn answers pending
  approvals as cancelled before the turn is cancelled.

### Event fidelity

- Each event carries `source` and `fidelity` (`exact`, `reported`, `inferred`,
  `unknown`).
- Missing protocol fields are marked unknown and not filled in. A file read
  without a reported range has `rangeKnown: false`; an edit that cannot be
  reconstructed has `fullContent: false`; a command without an exit code has
  `exitCodeKnown: false`.

### Interface

- Three switchable faces: Rounds, Monitor and Chart. Drip is an overlay toggle
  on the current face, not a fourth face. Monitor is the default.
- Monitor: Activity, Files and Attention tabs; the Stage renders activity cards
  and has only METRICS and CHAT page tabs, with no FILE / DIFF / TERMINAL strip.
  The right column holds Agent Head, Usage, Agent Eggs and Agent Folder.
- Rounds: a desktop with a story strip, a character, and floating windows for
  Files, Agent Folder, Agent Eggs, Run, file versions and per-egg metrics.
- Chart: the Absence Report as a full page.
- Drip: a collapsed ball or pill. The desktop shell gives it its own
  always-on-top window; the browser uses Document Picture-in-Picture.
- Settings has four panes: Appearance (language, theme
  `nixie` / `ink` / `glass`, scheme dark / light, chat Markdown), Report WARN,
  Personalization (avatar skins and sound sets), and Agent Eggs filter profiles.

### Replay and Absence Report

- Replay rebuilds file content, agent state and the current Stage action from
  run events and snapshots, at 0.25× to 10×. It does not rebuild metrics,
  Agent Eggs or terminal bytes.
- Absence Report is computed in the web client from a run's event slice. The
  server does not compute it, and no LLM is called. It reports the timeline,
  reads, searches, changes, commands, MCP calls, processes, recoveries, loops
  and attention.
- Attention reasons: `command_failed`, `command_failure_streak`,
  `activity_stalled`, `process_left_running`, `outside_change`,
  `file_version_loop`, `command_retry_loop`. Thresholds and levels are
  configurable in Report WARN.

### Agent Eggs, Agent Folder and metrics

- Agent Eggs come from the Windows Job Object or Linux eBPF. When the kernel
  helper is unavailable, process-table sampling is used and marked `sampled`.
  Processes are classified as `primary` or `tool`; the panel lists primary eggs
  and folds tools into counts.
- Docker container eggs use `docker events` for lifecycle and `docker stats` for
  resources. Containers use synthetic pids and are attributed only when started
  inside a command window.
- Agent Folder lists files the agent read, wrote or edited. Read versions
  accumulate the line ranges the agent saw; write and edit versions are complete
  files. Diffs use complete versions only.
- Metrics are sampled every 5 seconds for the agent tree, each egg, Docker
  containers and the host: CPU, RSS, VSZ, threads, handles (Windows only) and
  IO. The live ring holds 300 frames; SQLite stores chunks with 30-day retention.
- Monitor's run selector shows each run's event count, duration, start time and
  activity counts.

### Archives and proxy

- The SQLite archive supports paged event replay, archive deletion and session
  retention through `ABSENCE_SESSION_RETENTION_DAYS` and
  `ABSENCE_MAX_ARCHIVED_SESSIONS`.
- `absence proxy -- <cmd>` and `POST /api/acp-proxy/sessions` forward ACP lines
  unchanged and project events from a side tap. The proxy does not answer
  requests on behalf of the client.
- CLI commands: `absence`, `absence serve`, `absence proxy`.

### Packaging

- Windows releases include a portable ZIP (`Absence-0.5.0.zip`) alongside the
  NSIS installer. Linux releases include an AppImage and a `tar.gz`.
- Release assets are named `Absence.Setup-<version>.exe`,
  `Absence-<version>.zip`, `Absence-<version>.AppImage` and
  `Absence-<version>.tar.gz`.

### Fixes

- An agent's startup chunk is treated as metadata, not as a speaking turn; new
  sessions no longer stay stuck in speaking.
- The UI unlocks when a stop is not acknowledged.
- Silent overflow and forced watchdog settlement are reported as errors.
- Streamed tool output accumulates instead of keeping only the last chunk.
- ACP tool calls accept argv arrays and a null `rawInput` without inventing
  values.
- File read ranges are not inferred from content line counts; a missing range is
  reported as unknown.
- JSON-RPC `error.data` detail is kept in error events.
- The ACP proxy releases handles when both ends close.
- Windows shims are resolved by `PATHEXT`, and batch files are spawned safely.
- Closing a driven session reaps its command subtree.
- An orphaned Linux server detects its dead parent.

## Breaking changes

- The per-product adapters, `PiAdapter`, `CodexAdapter` and `DshAdapter`, were
  removed. Agents run through ACP profiles.
- The `codex app-server` client and the exec-server shell takeover were removed.
  `ABSENCE_CODEX_EXEC_SERVER` and the related `ABSENCE_CODEX_*` tuning variables
  no longer exist.
- `AbsenceShell`, `ExecServer`, `CodexShell` and `ShellEnvironment` were removed.
  `ABSENCE_PI_TOOLS` was removed with them.
- Capability configuration management was removed. Absence no longer reads or
  writes the agent's `mcp.json`, skills or `config.toml`.
- Pi private session file merging was removed. History comes only from the
  Absence archive. Existing JSONL archives are imported once on first access;
  the `piSessionFile` and `piSessionId` column names remain for compatibility.
- Absence-implemented slash commands (`/model`, `/skill`, `/mcp`, `/thinking`)
  were removed. Slash lines are forwarded verbatim, and `/auth` is the only local
  action.
- `GET /api/sessions/:id/commands/:name/options` was removed. Command options
  come from the agent's `configOptions` and `available_commands_update`.
- The `capabilities` field in session snapshots and state was removed, and
  `AgentProfile.discoverCapabilities` was removed.
- The Classic layout was removed: left rail, central Stage, right rail, the
  FILE / DIFF / TERMINAL / LIVE content tabs, rail panel order,
  collapse-on-content, and the Absence Report overlay. The faces and the Chart
  page replace them.
- Settings changed with the layout. The old `amber` / `blue` / `green` color
  theme was replaced by the `nixie` / `ink` / `glass` themes with dark and light
  schemes. Avatar skins moved into the Personalization pane.
- The server must be restarted and the browser hard-refreshed
  (`Ctrl+Shift+R`) after upgrading.
- npx fallback stays disabled unless `ABSENCE_ALLOW_NPX=1` or `allowNpx: true`
  is set. Absence does not download agents implicitly.

## Known limitations

- Avatar skins, sound sets and Agent Eggs filter profiles are stored in the
  installation directory. In a packaged application with a read-only directory,
  uploads fail.
- Agent Eggs are exact only when a Windows helper holds the process handle or
  Linux eBPF sees the process. Sampled mode can miss short-lived processes,
  concurrent commands can be attributed to a neighbouring command, and orphans
  are not attributed. The UI provides no kill action. Closing a session Absence
  drives reaps its command subtree.
- The ACP semantic layer depends on what the agent reports. A missing tool
  `kind` is handled by field-shape rules; missing `locations` leaves the file
  range unknown.
- Transcript reading covers only Pi and Codex layouts.
- The terminal mirror is produced by the server when Absence starts an agent in
  a PTY, but the current web interface does not connect to the terminal
  WebSocket.
- Replay does not rebuild metrics, the Agent Eggs panel or terminal bytes.
- Absence Report does not call an LLM and does not parse command semantics.
  Missing exit codes are reported as unknown. An unrecovered failure stays high
  regardless of configured thresholds.
- The archive keeps at most 10,000 events while a session runs. Streaming
  messages and thinking events are not persisted.
- Docker observation requires a reachable daemon. Containers started outside a
  command window are not attributed, and buildx infrastructure is filtered out.
- Metrics have a 5-second minimum cadence; shorter processes may never appear in
  a curve. Linux reports no handle counts, and IO readings depend on
  `/proc/<pid>/io` being readable.
- The picker has no UI for editing a profile's launch line and no allowNpx
  switch; both are set through environment variables, `~/.absence/agents.json`
  or the HTTP API.
