# Absence v0.3.0 —— Codex、DSH 与 shell 接管

[English](v0.3.0.md) | [简体中文](v0.3.0.zh-CN.md)

> 本文描述 v0.3.0 发布时的状态。下文提到的 Codex app-server 客户端、exec-server
> shell 接管、AbsenceShell、ExecServer、CodexShell、ShellEnvironment，以及 Codex
> 与 DSH 各自的专用适配器，均已在 v0.5.0 移除。v0.3.0 的原文用现在时描述这些
> 内容，在 v0.5.0 之后属于错误。当前接入方式见 [v0.5.0](v0.5.0.zh-CN.md)。

v0.3.0 把 Absence 从 Pi 扩展到 Codex 与 DSH。当时 Absence 通过 `codex app-server`
驱动 Codex，并通过 loopback exec-server 接管它的 shell；DSH 则通过它的 ACP server
接入。这三种机制都已在 v0.5.0 移除。

## 用户可见变化

### Codex 运行时

- 项目选择器可以选择 Codex；`ABSENCE_AGENT=codex` 也可以在不使用选择器时选中它。
- Absence 驱动 `codex app-server`，即 Codex 为观察器定义的 JSON-RPC 通道。与
  `codex exec --json` 不同，它携带 item id、call id 与时间戳，因此命令的生命周期
  能与它拉起的进程精确配对。
- Stage、Activity、Replay、Absence Report、Agent Eggs、Agent Folder 与聊天命令
  （`/model`、`/thinking`、`/permission`）照常工作。Web 端仍然只消费
  `AbsenceEvent`。

### DSH 运行时

- Absence 启动 `dsh --profile acp`，即 DSH 的 ACP server，并通过 stdio 上的
  JSON-RPC/NDJSON 驱动它。`DshClient` 是传输层，`DshAdapter` 把 `session/update`
  通知映射为 `AbsenceEvent`。
- message、thinking、tool、file、command、search 事件都会映射；`usage_update`
  转为 context 使用量。
- DSH 的读取结果会被解包：`<path>…<content>NN: line…` 包装被去掉，使 `file_read`
  与 Pi 的纯文本形状一致。
- 每次 shell 工具调用都会打开一个 `ProcessWatcher` 窗口（`tool_call` 时 `begin`，
  `tool_call_update` 时 `end`），因此 Agent Eggs 能看到 agent 拉起的进程。
- `session/request_permission` 成为 `approval` 事件；用户选中的 ACP option id 会
  回传给 agent。
- DSH 从显式路径（`ABSENCE_DSH_BIN` 或已保存路径）或 `PATH` 上的 `dsh` 定位。
  配置使用 `ABSENCE_DSH_BIN`、`ABSENCE_DSH_PROFILE`、`ABSENCE_DSH_HOME`、
  `ABSENCE_DSH_PROVIDER` 与 `ABSENCE_DSH_MODEL`。

### Codex 的 shell 接管

Pi 的 shell 属于 Absence（`AbsenceShell`），因此 Absence 能看到 Pi 命令拉起的
每个进程。Codex 在自己的进程里运行，无法沿用这种方式，于是 Absence 启动一个
loopback exec-server，用 `environment/add` 注册，并把线程固定到它上面。随后
Codex 把每条命令作为 `process/start` 交给 Absence，由 Absence 自己启动进程。

这解决了两类观察缺口：

- 分离启动（`Start-Process`、后台守护进程）此前会经 shell（`explorer.exe`）绕出
  Job Object，从 Agent Eggs 中消失。它改为 Absence 的子进程，按普通进程归因。
- 退出可以在子进程关闭时直接观察到，不再依赖进程树被整批杀死时可能丢失的内核
  消息。

`ABSENCE_CODEX_EXEC_SERVER=0` 可回退到 Codex 自己的 executor；观察器仍然运行，
但受旧有边界限制。

### 真实 PTY

Absence 使用 `node-pty`（Windows 上是 ConPTY）支持 `tty: true`。Ctrl+C 有效：
`process/signal interrupt` 以进程树 kill 应答。

### Windows 上的 Agent Eggs 退出修复

整棵进程树被一次性杀死时，Job Object 完成端口可能丢一条 `EXIT_PROCESS` 消息。
观察器改为同时等待每个进程句柄（`RegisterWaitForSingleObject`），这是不会丢失的
内核信号。

### 会话归因

环境标记只用于排除其他会话的进程，不再作为归因的必要条件。Linux 采集因此可用。

### 可配置的 Absence Report 注意力

- `command_failed` 只在一个 run 内失败命令达到可配置数量后触发（默认 5），并
  使用可配置等级。
- `command_failure_streak` 在连续失败达到可配置数量、中间没有成功命令时触发
  （默认 3，等级 medium）。
- `activity_stalled` 在 run 处于实时状态、且连续可配置秒数没有事件时触发
  （默认 3600 秒，等级 medium）。
- 所有阈值与等级都在 Settings 对话框的 **REPORT WARN** 栏设置（等级：
  none / low / medium / high）。未恢复的失败不受阈值影响，始终为 high。

### 自定义音效集

- 可按事件（`attention`、`complete`、`approval`）在 Settings 对话框上传音频，
  替换合成的 WebAudio 提示音。没有文件的事件继续使用内置提示音。
- 服务端把音效集存到 `sound-sets/<set>/<event>.<ext>` 与 `active.json`，并在
  `/sound/<event>` 提供当前音效集，支持 HTTP Range；`?set=` 可试听指定音效集。
- Web 端提供预览、清除与激活操作。

### 运行时发现与选择器

- `agents/PiBin.ts` 按顺序从配置路径、`ABSENCE_PI_BIN`、全局 npm 安装、Absence
  自身依赖树解析 `@earendil-works/pi-coding-agent` 包，并报告来源与版本。SDK 通过
  `loadPiSdk()` 加载，不再使用裸模块说明符。
- `GET` / `POST /api/runtimes` 与 `~/.absence/runtimes.json` 持久化二进制路径；
  `ABSENCE_CODEX_BIN` 为 Codex 提供初始值。选择器新增 runtime paths 面板，每个
  runtime 带一个可用性圆点。
- 请求的 runtime 无法启动时，会话以错误结束并在选择器中显示。启动失败
  （`ENOENT`）按事件处理，不会导致服务端崩溃。

### 聊天 dock 与 Settings

- 对话始终位于 Stage 之上，report、file、diff、terminal 面板不会遮住它。
- 新增 `APPEARANCE` 设置 *collapse on content*：打开内容页时折叠聊天历史。默认
  关闭。
- Settings 对话框有四个栏：`APPEARANCE`（主题、面板顺序、collapse on content）、
  `REPORT WARN`、`PERSONALIZATION`（头像皮肤与音效集同栏）与 `EGGS FILTER`
  （档案侧栏与 `+` 新建、标签编辑，以及一个默认关闭的 *display in activity*
  开关，用于在 Activity 中隐藏 LAID/DIED 行，同时仍在 Agent Eggs 中保留这些
  蛋）。

### 启动器与测试基础设施

- `start-absence.bat` / `.sh` 与桌面启动器只在输出旧于某个源文件时重建。
  `--force` 强制重建。
- 十一个检查脚本共用一个 harness（`scripts/checks/harness.ts`），提供
  `check()`、`finish()` 与 `waitFor()`。
- `npm run check:offline` 在一次进程启动中跑完所有离线检查；脚本清单只登记在
  `scripts/checks/run-offline.ts`。
- CI 在 Node 22 上运行 `check:offline`，与 `engines.node` 一致。
- `check-report.ts` 增至 72 项检查，`check-history.ts` 增至 63 条断言。
- `make-demo.mjs` 默认使用 `./absence-demo`。

## 破坏性变更

- 要求 Node `>=22.19`，与 `engines.node` 一致；CI 从 Node 20 换到 Node 22。
- `node-pty` 成为 `tty: true` 的新原生依赖，随包提供预编译二进制。
- 新增 Linux 安装包：`desktop:dist` 在 Windows NSIS 安装器之外同时产出 AppImage
  与 `tar.gz`。
- 需要重启服务器并硬刷新浏览器（`Ctrl+Shift+R`）。
- 新增环境变量：`ABSENCE_AGENT=codex|dsh`、`ABSENCE_CODEX_BIN`、
  `ABSENCE_CODEX_SANDBOX`、`ABSENCE_CODEX_APPROVAL`、
  `ABSENCE_CODEX_APPROVAL_DECISION`、`ABSENCE_DSH_BIN`、`ABSENCE_DSH_PROFILE`、
  `ABSENCE_DSH_HOME`、`ABSENCE_DSH_PROVIDER`、`ABSENCE_DSH_MODEL`。
- v0.3.0 新增 HTTP 接口：`GET` / `POST /api/runtimes`；`GET` / `POST
  /api/sounds[...]` 与 `GET /sound/:event`。v0.2.0 的 egg-filter 与
  avatar-skin 接口保持不变。

在 v0.5.0 移除的能力：

- 各产品专用适配器，包括 `PiAdapter`、`CodexAdapter` 与 `DshAdapter`，已删除，
  `DshClient` 传输层也一并删除。agent 改由 [v0.5.0](v0.5.0.zh-CN.md) 描述的 ACP
  接入层驱动。
- `codex app-server` 客户端与 exec-server shell 接管已删除。
  `ABSENCE_CODEX_EXEC_SERVER` 不再存在。
- `AbsenceShell`、`ExecServer`、`CodexShell` 与 `ShellEnvironment` 已删除。
  `ABSENCE_PI_TOOLS` 随之移除。
- 读写 agent `mcp.json`、skills 与 `config.toml` 的 capabilities 配置管理已删除。
- Pi 私有会话文件合并已删除。历史现在只来自 Absence 归档；observe 模式仍会读取
  Pi 与 Codex transcript 以生成工具与 MCP 事件，但不把它们当作历史合并。
- Absence 自己实现的斜杠命令（`/model`、`/skill`、`/mcp`、`/thinking`）已删除。
  斜杠行按原文转发；`/auth` 是唯一的本地动作。
- `codex`、`execserver`、`shellenv`、`codexshell` 检查脚本随对应实现一并移除。

## 已知限制

- shell 接管的保证只适用于通过 exec-server 接入的 Codex。v0.5.0 移除该路径后，
  这些保证不再成立。
- v0.3.0 的 DSH 支持依赖提供 `--profile acp` 的 DSH 构建。v0.5.0 之后，DSH 通过
  ACP profile 启动，专用适配器不再存在。
- Absence Report 的注意力等级可配置，但未恢复的失败不受阈值影响，仍为 `high`。
- 面板顺序与 *collapse on content* 设置属于 Classic 布局，已在 v0.5.0 移除。
- Windows 退出修复减少了丢失退出消息的情况；归因仍取决于进程在 Job Object 中
  可见，或出现在采样的进程表中。
