# Absence v0.6.0 —— 只做旁观

[English](v0.6.0.md) | [简体中文](v0.6.0.zh-CN.md)

> 本文描述 v0.6.0。本版本移除了 v0.5.0 引入的 ACP 接入层：Absence 不再启动、
> 驱动或应答任何 agent，所有写回路径被拒绝。被移除的能力列在“破坏性变更”一节。

Absence 现在是旁观者。agent 在自己的终端、自己的会话、自己的账号下运行；Absence
读取这个 agent 本来就在写的东西，以及操作系统本来就知道的东西。三条只读通道喂同
一条事件管线——不是 Absence 发起的会话，同样能显示出来。

## 用户可见变化

### 三条观察通道

- **通道 A 转录尾随。** `observe/` 尾随 agent 软件自己写的会话文件（pi 格式，
  `ABSENCE_OBSERVE_PI_ROOT` 可覆盖根目录）。发现只列目标，不打开会话；选中目标
  （`POST /api/observe/watch` 或 CLI `absence observe`）才完整回填并开始监控。
  `ABSENCE_AUTO_ATTACH=1` 恢复按近期活跃度自动挂载。
- **通道 B ACP 代理。** 代理会话把 agent spawn 进持久化的观察会话（`acp-proxy`），
  注入 `ABSENCE_SESSION_ID` 做精确的进程归因，把客户端提示词投影为 run 边界。
  入口是 `absence proxy -- <command>`。
- **通道 C OS 旁观。** 全机扫描器（`ExternalScanner`）给每个观察会话分发其绑定的
  进程子树。默认 pi 只按无歧义的 1:1 配对绑定，并以进程工作目录限定项目范围；绑定
  始终跟随进程最后写入的转录——运行中切换过会话（`-c`、会话选择器）的进程不会再
  被错配回它启动时的那个文件。
- pi 进程有三种方式命名自己的会话，三种都能解析：`--session <绝对路径>`、
  `--session <id>`（经转录头匹配）以及裸 `pi`（项目工作目录加最近写入）。比较前会
  剥掉 Windows 扩展长度路径前缀（`\\?\C:\…`）。命令行证明不了的 pi 仍作为
  OS-only 目标列出：行标题用其工作目录，pid 单独成列。
- 内核级观察：选中正在运行的 pi 会给该 pid 挂一个专用观察者。Windows 上
  `agentwatch --target-pid <pid>` 把进程收进自己的 Job Object；Linux 上全机 eBPF
  流按祖先关系过滤。进程子树以事件形式上报，而不是采样；挂不上内核观察者时回退到
  进程表扫描。

### 观测台就是正门

- Web 应用即观测台：它列出转录、代理与历史，从不启动 agent。
- 观测台分两栏——一栏是正在运行的目标，一栏是历史。点击会话即开始监控，同一次点击
  之后变成“停止”；没有逐行停止按钮。运行中的行与历史行一样显示首个提示词。
- 启动器、“+ Chat”入口、聊天输入、斜杠面板、审批按钮与 `/model` 切换均已移除；
  审批卡片变成只读。
- 历史行（或 `/s/<id>` 深链）以只读方式重开归档，不再返回 404。OS-only 观察升级
  出转录时会把对话回填进去，归档里的进程事实不会被误当成转录历史而被“预热”掉。

### 如实地读一份转录

- 一次 `edit` 工具调用只算一条 `file_edit` 事实。pi 为同一个文件发来的是一组替换，
  逐条产出会让 feed 出现五行时间戳完全相同的记录、时间线标记互相重叠——只有最后
  一条点得到。新近的调用会从磁盘还原整文件前后状态（一条事件、`fullContent: true`）；
  较早的记录仍是一条事件，携带上报片段与合并 diff。
- 时间线泳道重新带上各自的时长：assistant 记录的 `durationMs` 在生成结束时关闭
  思考或回复，`toolResult` 的 `durationMs` 把命令放回真正执行的时刻，Shell 泳道
  不再盖住模型的思考时间。
- run 边界跟随当前通道：给进程观察折入转录后，run 索引从“活动爆发”切回用户回合，
  重建已经写下的行（它们此前被首个事件标成 `usage` / `tool_end`），并阻止爆发计时器
  关闭 agent 仍在写的回合。退役的爆发型会话会关闭其未完成的 run，而不是留下一条
  永远不会结束的 `running` 行。
- 中途接入是诚实的：回填分块流入（一条记录可能跨块），第一个 run 标记为
  `attach`/`truncatedBefore`、不臆造提示词；回填期间追加的内容在末尾一次读取。

### 归档与续传

- SQLite schema v5 新增 `sessions.channel`、`sessions.external_id`（观察身份）与
  `runs.boundary_source`。重启后重新接入复用归档行，不再复制一份；观察会话在
  `ABSENCE_ARCHIVE_SILENCE_MS` 无活动且无观察者时自动归档。
- SQLite schema v7 新增 `transcript_checkpoints`：已消费的字节偏移与前缀的 SHA-256
  与事件在同一事务里落盘。重启后只有前缀校验通过才继续合并，因此离线期间的追加会被
  补齐而不重复历史。转录被重写或截断时停止合并，观测台显示
  `transcriptResumeBlocked`；孤儿检查点会被丢弃，而不是让一次 flush 失败。

### 命令行

`absence` 是无界面入口：`serve`、`ls`、`observe`、`open`、`unwatch` 与 `proxy`。
`serve` 启动服务端（默认命令），`ls` 列出本机可监控的目标，`observe` 选中目标并
打印面板 URL，`open` 打印某个会话的面板 URL，`unwatch` 撤销监控租约但保留归档。
`ABSENCE_URL` 与 `ABSENCE_TOKEN` 用于访问已运行的服务端。

### 平台

- Windows 的 Docker 采集被强制关闭：不再探测 WSL daemon，也没有环境变量可以重新
  打开。其他平台的容器归因来自转录里的命令窗口。

## 破坏性变更

- Absence 不再驱动任何 agent。ACP 驱动栈（`AcpAdapter`、`AcpConnection`、
  `AcpSession`、权限桥、认证、config options、`AgentCatalog`、内置 profile 以及
  `createAdapter` 的真实路径）已删除。`createAdapter` 只解析 mock 夹具；其他会话
  一律按观察处理，写回路由返回 403。
- 聊天已移除：输入框、斜杠面板、审批按钮、`/auth` 与 `/model`，以及所有会写入会话
  的命令。`/model` 在 v0.5.5 引入，本版本移除；模型改在 agent 自己的终端里选择。
- agent 选择器、agent 发现、`~/.absence/agents.json` 自定义条目、ACP registry
  缓存、运行时发现以及 `ABSENCE_*_BIN` 覆盖不再作为启动路径存在。
  `ABSENCE_ALLOW_NPX` 与 `allowNpx` 随之移除。
- `GET /api/agents*`、`GET /api/runtimes*` 与会话写回路由已删除。启动会话改用
  `POST /api/observe/watch`。
- 没有终端镜像，也没有 PTY：Absence 从不启动 agent，因此没有可镜像的终端。
- 会话以观察身份标识，而不是以一次启动标识。channel 与 external id 都匹配到既有
  观察会话的归档行会被复用；旧的按产品区分会话键的方式已不存在。
- Windows 上 Docker 采集关闭，且没有环境变量可以重新打开。
- 桌面壳与浏览器打开的都是观测台；深链是 `/s/<sessionId>`。

## 已知限制

- 转录读取只支持 pi 格式。完全不写转录的 agent 仍可作为 OS-only 目标观察，但
  Absence 看到的是它的进程树、文件与命令，而不是它的对话。
- 把转录绑定到进程需要证据。当命令行既没给出会话文件也没给出会话 id，且没有任何
  单一进程是唯一候选时，目标按 OS-only 列出，其对话不会进入归档。有歧义的配对绝不
  猜测。
- 内核观察只依赖随仓库提交的原生助手。没有它时进程表扫描是采样式的：短命进程可能
  漏掉，孤儿进程不归因。
- Docker 观察以 daemon 可用为前提，命令窗口之外启动的容器不归因；Windows 上容器
  采集关闭。
- Absence 从不启动、恢复或停止被观察的 agent。关闭面板只是撤销监控租约；agent 继续
  运行，它派生的进程也一样。
- Replay 与 Absence Report 仍基于归档事件切片工作，仍不重建指标、Agent Eggs 或
  终端字节。现在已经没有终端字节，因为 Absence 不再持有终端。
- 重新监控同一目标会刷新其监控租约，而不是新建第二个；重启后重新接入复用归档行，
  而不是复制会话。
- Linux 内核观察需要 `CAP_BPF` 与 `CAP_PERFMON`（或 root）。没有它们时加载器拒绝
  启动，会话回退到轮询，并在目标状态里给出原因。
- `absence ls`、`observe`、`open`、`unwatch` 是运行中服务端的薄客户端；它们读取
  `ABSENCE_URL` 与 `ABSENCE_TOKEN`，而不是本地归档，因此没有服务端时无从询问。
