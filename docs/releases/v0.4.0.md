# Absence v0.4.0 — Persistence, metrics and verification

[English](v0.4.0.md) | [简体中文](v0.4.0.zh-CN.md)

> These notes describe v0.4.0 as released. The Classic layout described here —
> right rail, Stage pages and the FILE / DIFF / TERMINAL / LIVE content views —
> was replaced by the Rounds / Monitor / Chart faces in v0.5.0.

v0.4.0 built on the runtime integrations of v0.3.0. It moved session history to
SQLite, added resource metrics, and made `npm run verify` the complete
acceptance gate.

## User-visible changes

### SQLite session history

- Sessions, events, runs and file versions were stored in SQLite at
  `~/.absence/absence.db` in WAL mode.
- Legacy JSONL archives were imported once and retained as a backup.
- History was indexed incrementally, and historical Activity was loaded by run
  without loading an entire session into the browser.
- File versions had their own index, independent of the History view.

### Resource metrics

- CPU and RSS were sampled for the agent's primary eggs and exposed as metrics
  frames over WebSocket.
- The newest 300 frames were kept in the live ring.
- Longer ranges and historical sessions were read from SQLite metric chunks,
  with 30-day retention and session-level averages.
- The right-rail METRICS panel and the full Stage dashboard supported selecting
  an egg and viewing `1m`, `5m`, `30m`, `1h` and `all` ranges.
- Exited eggs stopped contributing to lifetime averages at their observed exit.
- The last sample of an exited egg remained available, and its summary was
  marked as exited.

### Stage and state model

- METRICS became the Stage's default page. FILE, DIFF, TERMINAL and LIVE were
  content views; replay remained event-and-snapshot based.
- Incremental folding kept Agent Eggs, History and Activity correct while the
  live event window slid, without rebuilding the whole window for every event.
- Agent file views preserved gaps in unread line ranges and could switch
  between recorded versions of the same path.

### Verification

- `npm run verify` ran the workspace typechecks, the production Web build and
  every offline acceptance check.
- Offline coverage included metrics storage, incremental folding and
  outside-change attribution.
- The live mock History check covered 75 assertions, including pagination,
  replay, the Metrics default page, file gaps and version switching.
- Dedicated checks validated the desktop server bundle and the standalone
  server lifecycle.

## Breaking changes

- Node `>=22.19` was required. SQLite was provided by Node's built-in
  `node:sqlite`, as declared in `package.json` and `.nvmrc`.
- `ABSENCE_STATE_DIR` had to point at a filesystem that supported SQLite WAL, and
  two concurrently running instances could not use the same database.
- The server had to be restarted and the browser hard-refreshed
  (`Ctrl+Shift+R`).
- Existing JSONL archives were imported automatically on first access and
  retained as a backup.
- The UI layout at v0.4.0 was replaced in v0.5.0. No migration action was
  required, but the METRICS default page and the FILE / DIFF / TERMINAL / LIVE
  content views no longer exist.

## Known limitations

- Metrics were retained for 30 days by default; older chunks were deleted
  unless the retention setting was changed.
- Resource metrics were sampled on a fixed cadence. Processes shorter than the
  cadence could be absent from the curves.
- Historical metrics were read from persisted chunks; a range beyond the live
  ring required those chunks to have been written.
- File gaps in Agent Folder were preserved from what the agent reported. When a
  read carried no line range, the view marked the range as unknown.
- The Classic layout described above was a v0.4.0 interface. The faces
  introduced in v0.5.0 changed the reading model, not the stored data.
